# Product Requirements Document (PRD) — VendorBridge

## Problem Statement

Organizations experience high manual inefficiencies, fragmented communications, and a lack of auditability in their procurement workflows. Managing relationships between vendors, Requests for Quotations (RFQs), quotation comparisons, multi-level approvals, purchase order (PO) generation, and invoicing is currently paper-based or scattered across disparate tools. This leads to slow processing times, human errors in tax calculations, unauthorized purchases, and untrackable spend analytics.

## Solution

VendorBridge is a centralized, role-based Procurement & Vendor Management ERP. Built with a Node.js (Express) backend API and a Next.js App Router frontend, it automates the full procurement lifecycle:
1. **Vendor Lifecycle:** Centralized registration and approval management.
2. **RFQ & Quotation Flow:** Digital RFQ creation, vendor bidding, and side-by-side quotation comparisons.
3. **Structured Approvals:** Sequential L1 (Procurement Head) and L2 (Finance Manager) workflow.
4. **PO & Invoice Automation:** Thread-safe sequential document numbering, automatic GST splitting (9% CGST / 9% SGST), and email delivery via Resend.
5. **Security & Transparency:** HTTP-only cookie session handling, role-based middleware, and database-enforced immutable activity logs.

## User Stories

1. As an anonymous user, I want to sign up for an account with my personal information (first/last name, email, phone, role, country, and photo), so that I can request access to the platform.
2. As a newly registered user, I want my account status to default to `Pending`, so that admins can verify my identity before I gain access.
3. As a registered user in `Pending` status, I want to be blocked from logging in, so that unauthorized personnel cannot view the system.
4. As a registered user, I want to log in securely using my email and password, so that I can access my dashboard and tasks.
5. As an Admin, I want to view a table of all registered users and approve or reject their access, so that I can manage system members.
6. As a Procurement Officer, I want a dashboard showing active RFQs, pending approvals, monthly PO counts, and overdue invoices, so that I can monitor day-to-day procurement tasks.
7. As a Manager, I want a dashboard showing only the approvals currently awaiting my review, so that I can process them quickly.
8. As a Vendor, I want a dashboard showing my assigned RFQs, submitted quotations, and received POs, so that I can fulfill my supplier duties.
9. As a Procurement Officer, I want to register a new vendor profile with company details (name, category, GSTIN, phone, address), so that they are added to the procurement database.
10. As an Admin, I want to change a vendor's status to `Active` or `Blocked`, so that I can control which suppliers are allowed to bid.
11. As a Procurement Officer, I want to create an RFQ with basic details, dynamic line items (item name, quantity, unit), and drag-and-drop file attachments, so that I can specify what goods or services are required.
12. As a Procurement Officer, I want to assign multiple active vendors to a new RFQ, so that only qualified suppliers are invited to bid.
13. As a Procurement Officer, I want to save an RFQ as a `Draft` or publish it as `Published`, so that I can refine my requirements before inviting vendors.
14. As a Vendor, I want to view the details and attachments of RFQs to which I've been invited, so that I can formulate an accurate bid.
15. As a Vendor, I want to submit a quotation responding to an RFQ, inputting unit prices, delivery timelines, and payment terms, so that my proposal can be evaluated.
16. As a Vendor, I want to save my quotation as a `Draft` and edit it before the RFQ deadline, so that I can adjust my pricing as needed.
17. As a Procurement Officer, I want to view a side-by-side comparison of all quotations received for a specific RFQ, highlighting the lowest price in green and showing vendor rating indicators, so that I can select the best vendor.
18. As a Procurement Officer, I want to click 'Select' on a quotation in the comparison screen to mark the quotation as `Pending Approval` and automatically trigger the approval workflow, so that managers can review my choice.
19. As an L1 Approver (Procurement Head), I want to see the quotation summary and enter approval remarks to approve or reject a request, so that it can proceed to L2 or return to the Officer.
20. As an L2 Approver (Finance Manager), I want to approve a request that has cleared L1, so that the purchase is finalized.
21. As a Procurement Officer, I want the system to auto-generate a unique sequential Purchase Order (`PO-YYYY-NNNN`) the moment the L2 manager approves the quotation, so that we have an official order document.
22. As a Procurement Officer, I want to generate a GST-compliant invoice from an approved PO, automatically splitting the 18% tax into 9% CGST and 9% SGST, so that we have an accurate record of the transaction.
23. As a Procurement Officer, I want to download the invoice as a PDF, print it, or email it directly to the vendor's email address using Resend, so that we can distribute the billing record.
24. As a Procurement Officer, I want to mark an invoice as `Paid`, so that the corresponding Purchase Order is marked as `Fulfilled` and the transaction is closed.
25. As any logged-in user, I want to view a chronological feed of activity logs filtered by type (RFQ, Approvals, Invoices, Vendors) matching my role permissions, so that I can track changes.
26. As an Auditor, I want to be guaranteed that no user can update or delete records from the activity logs, so that the audit trail is completely trustworthy.
27. As an Admin or Manager, I want to view reports showing total spend, active vendor counts, PO fulfilment rates, and monthly spend charts, so that I can analyze procurement trends.
28. As an Admin, I want to export report data to a CSV file, so that I can share it or perform offline analysis.

## Implementation Decisions

### Core Modules & Responsibilities
1. **Authentication Module:**
   * Performs user registration and hashes passwords using `bcrypt`.
   * Restricts login for accounts with a `Pending` status.
   * Issues JWTs stored in secure, HTTP-only, SameSite cookies.
2. **Vendor Management Module:**
   * Manages supplier registry and categories.
   * Prevents blocked vendors from being invited to new RFQs.
3. **RFQ & Quotation Module:**
   * Implements a multi-step form wizard for RFQ creation.
   * Handles draft and published quotation submissions.
   * Calculates subtotal, 18% GST (split into 9% CGST / 9% SGST), and grand totals.
4. **Approval Workflow Module:**
   * Runs the L1 (Procurement Head) -> L2 (Finance Manager) workflow.
   * Rejection resets the state back to the Procurement Officer for vendor re-selection.
5. **PO & Invoice Module:**
   * Auto-generates unique `PO-YYYY-NNNN` and `INV-YYYY-NNNN` sequential numbers using database auto-increments padded to 4 digits.
   * Generates PDF invoices and integrates the `resend` library for email delivery.
6. **Activity Log Module:**
   * Implements write-once audit logs.
   * Restricts updates and deletes via PostgreSQL database triggers.
7. **Reports & Analytics Module:**
   * Aggregates spend, active vendors, and PO fulfilment rates via database queries.

### Integration Contracts
* **Frontend-Backend Bridge:** Next.js proxies all API requests via rewrite rules (e.g. `/api/v1/*` maps to the Express server port), providing same-origin cookie transmission.
* **External Integrations:** Serves file uploads from local disk static directories (`/backend/uploads/`) and delivers emails using `resend`.
* **Database migrations:** Managed using Prisma migration scripts, including custom SQL scripts to bind the activity log block triggers.

## Testing Decisions

### Test Strategy
To maintain velocity while ensuring system robustness, we will prioritize **Integration and Contract testing** of key business transitions rather than testing internal implementation details.

1. **Authentication and Authorizations:**
   * Test user signup creates a `Pending` user.
   * Test logging in as `Pending` fails.
   * Test Admin activation changes status to `Active`.
   * Test role-based middleware blocks access to unauthorized endpoints.
2. **RFQ and Quotation Validation:**
   * Test creating an RFQ and publishing it.
   * Test submitting a quotation and verifying the tax/total math.
3. **Workflows & Serial Generation:**
   * Test selecting a quotation creates L1 pending approval.
   * Test L1 and L2 approval sequence.
   * Test that L2 approval automatically creates the PO with correct numbering (`PO-YYYY-NNNN`).
   * Test generating an invoice splits CGST/SGST correctly and assigns number `INV-YYYY-NNNN`.
4. **Log Immutability:**
   * Attempt to execute SQL `UPDATE` and `DELETE` on the `activity_logs` table and assert that the database trigger throws an error, failing the operation.

---

## Out of Scope

* **Real payment gateway integration:** All payment statuses are manually actioned using the "Mark as Paid" interface.
* **Multi-language (i18n) support:** The application interface is delivered solely in English.
* **Mobile native application:** Responsive web design works on desktop browsers and mobile screens, but no native app is built.

## Further Notes

* **Configuration Management:** A `.env.example` file will detail all environment variables, including `RESEND_API_KEY`, database credentials, and development ports.
* **Database Seeding:** A database seeding script (`npm run db:seed`) will be included to instantiate the initial `Active` Admin account, active vendors, and standard categories to enable immediate evaluation.
